## Wave 1 — fix first (proven breakage + multi-mode security)

### 1. S2 — PostgresVectorStore query methods are broken (HIGH, proven live)
- `tools/shared/impls/postgres_vector.py:182-190` (`query_dense`): the SQL has 4 placeholders, params list 3 — every call fails. Fix: drop the redundant `WHERE 1 - (embedding <=> %s) > -1` clause (a tautology for cosine distances) OR add the second vec param; simplest is removing the WHERE line and binding `[vec, vec, limit] + filter_params` in SQL order (select-similarity vec, ORDER BY vec, LIMIT, then filter params last in the WHERE). Careful: placeholder order is textual — write the WHERE before ORDER BY, so params must be `[vec] + filter_params + [vec, limit]`.
- `:214-223` (`query_sparse`) and `:239-250` (`query_hybrid`): filter params currently land after LIMIT — reorder to `[q] + filter_params + [q, limit]` (sparse) / `[vec, q] + filter_params + [q, limit]` (hybrid) matching SQL text order.
- Tests (the gap that hid this): extend `tests/test_backend_contracts.py` with PG-gated cases (auto-skip, `pg_dsn` fixture): query_dense ±filter, query_sparse ±filter, query_hybrid ±filter — assert results AND that no ProgrammingError. Effort S+test.

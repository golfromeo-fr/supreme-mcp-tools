# M4/H4 — second-node runbook (2026-09-10, feature/m4-multihost)

Prereqs shipped on this branch: `MCP_USERS_BACKEND=db` (H1) and
`MCP_STATE_BACKEND=db` (H2 — masks + inventory via `state_docs.py`),
plus the `env_auth_snapshot` mirror (H2b) with its additive
`restore_missing_env_vars()`.

## Node bootstrap (second node / podman container)

1. **Code**: same image / same commit as node 1 (`main` or the release tag).
2. **`.env`**: start from node 1's `.env`, then reconcile. The authoritative
   diff lives in the shared backend:
   ```bash
   MCP_STATE_BACKEND=db TURSO_DATABASE_URL=<shared-url> \
     python3 - <<'EOF'
   from launcher.env_manager import load_env_auth_snapshot, restore_missing_env_vars
   snap = load_env_auth_snapshot()
   if snap is None:
       raise SystemExit("no env_auth_snapshot in the shared backend — run "
                        "save_env_auth_snapshot() on node 1 first")
   print(restore_missing_env_vars(snap, apply=True))   # additive only
   EOF
   ```
   The restore is **additive**: variables node 2 already has (its own
   `MCP_UI_SECRET`, node name, etc.) are reported as `kept` and never
   overwritten. Review the report before trusting it.
3. **Tool config.json files** (`auth` sections): copy from node 1 (snapshot
   `auth` documents them) — these are the tools' import-time bootstrap and
   stay node-local by design (H2b deferral).
4. **Backends**: users + state docs must point at the SAME network
   Turso/PG as node 1 (`MCP_USERS_BACKEND=db`, `MCP_STATE_BACKEND=db`,
   `TURSO_DATABASE_URL`/`POSTGRES_*`). Remember: a local
   `file:` Turso URL is NOT shareable — use turso://cloud or TCP-served
   libSQL. Data planes (Qdrant/PG/memory Turso) likewise.
5. **Start**: same `startlauncher` command; seeds converge (only ADDS
   missing users; env-pinned keys sync). Verify per-tool boot lines:
   `MCP_AUTH_MODE=multi — identity gate active` ×6 and
   `[M4] state docs: SQL backend active`.

## Snapshot maintenance

- Regenerate after env/auth changes on node 1:
  `save_env_auth_snapshot()` (or expose it later as a central endpoint).
- The snapshot is the CLUSTER bootstrap source; treat it like a secret
  (it contains raw API keys).

## LB (v1)

- Health checks: `GET /health` per tool + central `/health` (all exist).
- `/mcp` (stateful) needs sticky sessions (source-IP or cookie);
  `/mcp-stateless` floats freely — prefer it everywhere.
- Any node's central API (8200) is equivalent; give humans one hostname.

## Podman notes (from the 2026-09-08 decision)

- Rootless podman publishes 8000-8200 fine.
- Nodes must hold NO unique local state: `logs/` and any transition files
  go in DECLARED volumes; everything mutable lives in the network backends.
- One podman network so nodes reach Turso/PG/Qdrant by name.
- "Identical .env" becomes "same image, one mounted .env".

## Current honest limits (see the M4 design doc's build status)

- Runtime mask pushes apply only to the node that got the API call.
- Writes are last-writer-wins per document; run inventory sync on one node.
- env/auth values stay node-local bootstrap (H2b mirror is adopt-only).
